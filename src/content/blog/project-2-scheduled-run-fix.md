## 무슨 일이 있었나

지난 글에서 AI 뉴스 카드뉴스를 **매일 아침 자동으로** 만들어 슬랙으로 받는 구조를 만들었다. 노트북이 꺼져 있어도 깃허브의 클라우드 실행 기능(GitHub Actions)이 정해진 시간에 알아서 돌린다는 계획이었다.

그런데 다음 날 아침 슬랙에 아무것도 오지 않았다. 그다음 날도 마찬가지였다. 이틀 연속 카드가 안 와서 꽤 답답했다. 손으로 실행 버튼을 누르면 3분 만에 잘 만들어지는데, 정해진 시간에 저절로 돌지만 않았다.

## 1. 실행 기록부터 봤다

GitHub Actions에는 실행 기록이 남는다. 기록마다 **무엇 때문에 실행됐는지**가 적혀 있는데, 손으로 누른 실행은 `workflow_dispatch`, 예약으로 돈 실행은 `schedule`로 나온다.

기록을 보니 **`schedule`이 0건**이었다. 코드가 돌다가 실패한 게 아니라, 아예 시작되지 않은 것이다. 그래서 코드보다 "예약" 쪽을 의심했다.

AI 코딩 도구에 이렇게 물어보면 확인해 준다.

```text
GitHub Actions 예약 실행(schedule)이 돌지 않는 것 같아.
최근 실행 기록을 실행 이유(event)별로 보여 주고,
예약 실행이 한 번이라도 있었는지 확인해 줘.
```

## 2. 첫 번째 시도: 정각을 피했다

깃허브 문서에는 "매시 정각은 실행이 몰려서 늦어지거나 빠질 수 있으니 다른 분으로 정하라"는 안내가 있다. 처음 예약은 정각(오전 8시)이었다. 그래서 **오전 7시 23분**처럼 정각이 아닌 시각으로 바꿨다.

다음 날 아침에도 오지 않았다. 원인은 이게 아니었다.

설정도 하나씩 다시 봤다. 예약은 기본 가지(main)에 있어야 돌고, 시각은 한국 시간이 아니라 세계 표준시(UTC)로 적어야 한다. 둘 다 맞게 되어 있었다. 손으로 실행하면 항상 성공했으니 코드 문제도 아니었다.

## 3. 점검용 예약으로 원인을 좁혔다

추측만으로는 끝이 안 나서 **10분마다 한 번씩 도는 아주 작은 점검용 예약**을 따로 걸었다. 글자 한 줄만 찍고 끝나는 거라 비용 걱정도 없다. 이것조차 안 돌면 "이 저장소에서는 예약 자체가 안 된다"는 뜻이 된다.

결과는 0건이었다. 20분 넘게 기다려도 한 번도 돌지 않았다.

찾아보니 **무료 개인 계정의 비공개 저장소에서는 예약 실행이 사실상 돌지 않는다**는 사용자 보고가 있었다. 딱 우리 상황이었다. 다만 깃허브 공식 문서에서 이 내용은 찾지 못해서, 직접 시험해서 확인하기로 했다.

```text
GitHub Actions 예약이 이 저장소에서 실제로 도는지 확인하고 싶어.
10분마다 한 줄만 출력하는 임시 워크플로를 만들어 줘.
확인이 끝나면 지울 거야.
```

## 4. 저장소를 공개로 바꿨다

저장소를 공개하면 예약이 돈다는 보고가 많았다. 다만 공개하면 **지난 커밋 기록까지 전부** 누구나 볼 수 있게 된다. 그래서 바꾸기 전에 먼저 점검했다.

- 지난 기록 전체에서 API 키처럼 생긴 문자열을 찾았다. 0건이었다. 키는 처음부터 코드가 아니라 저장소의 Secrets에만 넣었기 때문이다.
- 커밋에 남는 이메일이 개인 주소가 아니라 깃허브의 비공개용 주소(noreply)인지 확인했다.

```text
이 저장소를 공개로 바꾸려고 해.
바꾸기 전에 지난 커밋 기록 전체에서 API 키, 토큰, 개인 이메일 같은
공개되면 안 되는 내용이 있는지 찾아 줘.
```

공개로 바꾸자 **바로 예약이 두 번 돌았다.** 원인이 맞았다. 그런데 그 뒤로 정해 둔 시각(11시 47분, 12시 7분, 12시 17분, 12시 33분)의 점검 예약은 **모두 빠졌다.** 보조로 걸어 둔 카드 예약도 1시간이나 늦게 돌았다.

비공개 저장소 문제를 푼 것은 맞지만, 깃허브 예약은 공개 저장소에서도 **정해진 시각을 보장하지 않는다.** 이렇게까지 불안정한 줄은 몰랐다. 매일 아침 받아야 하는 카드에 쓰기에는 부족했다.

## 5. 시작 시각만 외부 서비스에 맡겼다

실행 자체는 GitHub Actions가 잘한다. 문제는 **언제 시작하느냐**뿐이었다. 그래서 시작 버튼만 다른 서비스가 정확한 시각에 눌러 주게 했다. 쓴 서비스는 **cron-job.org**(무료 예약 서비스)다. 정해진 시각에 정해진 주소로 요청을 보내 준다.

깃허브에는 "이 워크플로를 실행해 줘"라는 요청을 받는 주소가 있다. cron-job.org가 매일 그 주소로 요청을 보내면, 손으로 버튼을 누른 것과 똑같이 실행된다.

순서는 이렇다.

1. **깃허브 토큰 만들기**: 깃허브 설정의 Fine-grained tokens에서 새 토큰을 만든다. 저장소는 **이 저장소 하나만** 고르고, 권한은 **Actions: Read and write**만 준다. 토큰이 새어 나가도 할 수 있는 일이 이 저장소 실행뿐이 되게 하려는 것이다.
2. **cron-job.org에 예약 만들기**
   - URL: `https://api.github.com/repos/{계정}/{저장소}/actions/workflows/{워크플로 파일 이름}/dispatches`
   - 실행 시각과 시간대(Asia/Seoul)
   - 요청 방식: POST
   - 헤더 3개: `Authorization`에 `Bearer {토큰}`, `Accept`에 `application/vnd.github+json`, `Content-Type`에 `application/json`
   - 본문: `{"ref":"main"}`
3. **먼저 시험용으로 확인하기**: 진짜 카드를 만들면 비용이 드니까, 슬랙에 알림 한 줄만 보내는 시험용 워크플로를 따로 만들어 그걸로 먼저 확인했다.

처음 시험에서는 **401(인증 실패)** 이 났다. 깃허브가 토큰을 알아보지 못했다는 뜻이다. `Bearer` 뒤의 띄어쓰기, 헤더 이름 철자, 토큰 앞뒤 공백, 저장한 뒤 시험했는지 같은 흔한 원인을 하나씩 확인하고 다시 시험하니 성공했다.

그다음 **14시 50분으로 예약한 시험이 14시 50분 7초에 실행돼서** 슬랙에 알림이 왔다. 깃허브 예약이 1시간씩 늦던 것과 비교하면 확실히 달랐다.

```text
GitHub Actions 워크플로를 외부 예약 서비스(cron-job.org)에서 실행하려고 해.
1. 슬랙에 "몇 시에 실행됐는지" 한 줄만 보내는 시험용 워크플로를 만들어 줘. (손으로도 실행할 수 있게)
2. cron-job.org에 넣을 URL, 요청 방식, 헤더, 본문을 알려 줘.
3. 깃허브 토큰은 이 저장소의 Actions 실행 권한만 있게 만드는 방법을 알려 줘.
토큰 값은 대화에 붙여 넣지 않을 거야.
```

## 6. 같은 날 두 번 만들어지지 않게

이제 예약이 두 군데다. cron-job.org가 메인이고, 깃허브 예약도 보조로 남겨 뒀다(혹시 cron-job.org가 실패할 때를 대비해서). 그러면 둘 다 돌아서 **같은 날 카드가 두 번** 만들어질 수 있다.

그래서 실행할 때 **"오늘 이미 만들었으면 바로 끝내기"** 를 넣었다. 다룬 기사 기록에 오늘 날짜가 있으면 아무것도 하지 않는다. 실제로 공개 직후 늦게 돈 보조 예약이 "오늘 카드는 이미 만들었습니다"라며 바로 끝났다.

```text
이 프로그램이 하루에 여러 번 실행될 수 있어.
오늘(한국 날짜) 이미 만든 기록이 있으면 아무것도 하지 않고 끝나는 옵션을 추가해 줘.
예약으로 실행될 때만 그 옵션을 켜 줘.
```

이 과정에서 하나 더 배웠다. 자동 실행이 도는 도중에 내가 코드를 올렸더니, 실행이 끝나고 기록을 저장하는 단계에서 **충돌이 나서 기록이 빠졌다.** 그대로 두면 보조 예약이 "아직 안 만들었다"고 보고 카드를 또 만든다. 기록을 직접 넣고, 저장하기 전에 최신 내용을 먼저 합치게 고쳤다.

## 곁가지로 고친 것들

이틀 동안 손으로 돌리면서 다른 문제도 몇 개 보였다.

- **답이 조각나서 깨지는 문제**: 기사를 고를 때 AI가 웹 검색을 쓰면 답이 여러 조각으로 온다. 코드가 조각 사이에 줄바꿈을 끼워 넣어서 문장 한가운데가 끊겼고, 결과를 읽지 못해 실패했다. 조각을 그대로 이어 붙이게 고쳤다.
- **복사하면 글자가 바뀌는 문제**: 슬랙 메시지에서 게시물 문구를 복사하니 영어 따옴표가 깨지고 해시태그의 `#`이 빠졌다. 원본 문구를 텍스트 파일로도 같이 보내서, 파일에서 복사하게 했다.
- **엉뚱한 나라 그림**: 미국 경찰 이야기인데 이미지에 한국어 양식과 한국 경찰 같은 엠블럼이 나왔다. 기사 속 나라에 맞게 그리고, 한국 이야기가 아니면 한국 기관 표시를 넣지 않게 규칙을 추가했다.

## 배운 점

- **"자동"은 시작 시각까지 확인해야 자동이다.** 코드는 잘 돌아도, 정해진 시간에 시작되지 않으면 소용이 없다. 처음 만들 때 손으로만 시험하고, 예약으로 도는지는 확인하지 않았다.
- **깃허브 예약은 정확한 시각을 보장하지 않는다.** 비공개 저장소에서는 아예 안 돌 수 있고, 공개 저장소에서도 늦거나 빠진다. 정확한 시각이 중요하면 외부 예약 서비스로 시작만 맡기는 게 낫다.
- **원인은 작게 쪼개서 확인한다.** 카드 전체를 돌리며 기다리는 대신, 한 줄만 찍는 점검용 예약으로 "예약 자체가 도는가"만 따로 봤다.
- **공개 전에는 기록 전체를 본다.** 지금 파일만이 아니라 지난 커밋에 남은 내용까지 공개된다.

## 앞으로

- 내일 아침 7시 23분에 cron-job.org가 카드를 제시간에 실행하는지 확인한다.
- 같은 방식으로 매주 월요일 아침에 도는 AI 시트콤 영상(프로젝트 3)도 예약했다. 첫 자동 실행을 지켜볼 예정이다.
