## 무엇을 만들었나

AI와 함께 만든 작은 게임과 생활 도구를 한곳에 모아 두는 사이트를 열었다. 이름은 **오늘의 AI 작품**이다.

- 사이트: [today-ai-works.pages.dev](https://today-ai-works.pages.dev)
- 인스타그램: [@today_ai_works](https://www.instagram.com/today_ai_works/)
- 코드: [github.com/today-ai-works/site](https://github.com/today-ai-works/site) (공개)

흐름은 단순하다. 인스타에 작품 영상을 올리고, 영상을 본 사람이 프로필 링크를 눌러 사이트에서 바로 해 본다. 설치도 가입도 없다.

## 1. 사이트를 어떻게 만들었나

### 정한 것과 이유

| 정한 것 | 이유 |
|---|---|
| 호스팅은 **Cloudflare Pages** (무료) | 나중에 광고를 붙일 수 있다. GitHub Pages는 수익 목적 사이트에는 애매하다 |
| 저장소는 **하나**, 게임은 폴더로 | 게임마다 저장소를 나누면 주소가 흩어지고, 홈 · 약관 같은 공통 부분을 매번 복사해야 한다 |
| 휴대폰 · PC를 **한 페이지로** | 기기에 따라 조작만 바꾼다 (터치 · 마우스 · 키보드) |
| 게임 화면은 **세로 9:16** | PC에서도 세로 비율을 유지하면 녹화한 화면이 그대로 릴스 크기가 된다 |
| 빌드 과정 **없음** | HTML · CSS · JS 파일을 그대로 올린다. `main`에 push하면 1분쯤 뒤 자동 배포 |

GitHub에는 조직(`today-ai-works`)을 만들고 그 안에 저장소 `site`를 두었다. 조직 이름에는 밑줄을 못 써서 인스타 아이디(`today_ai_works`)와 달리 하이픈을 썼다.

AI에게 뼈대를 맡길 때는 이렇게 시키면 된다.

```text
AI로 만든 브라우저 게임을 모아 두는 정적 사이트 뼈대를 만들어 줘. 빌드 도구 없이 HTML/CSS/JS만 써.
- 홈(작품 카드 목록), 소개, 문의, 개인정보처리방침, 이용약관, 404 페이지
- 모든 페이지가 같이 쓰는 CSS 하나, 휴대폰 우선 반응형
- games/_template/ 에 새 게임을 만들 때 복사할 견본 게임(시작 화면 → 게임 → 결과 화면)
- 결과 화면 맨 아래에 사이트 주소 {사이트 주소}가 보이게
- README에 새 게임 올리는 순서를 적어 줘
```

### Cloudflare Pages에 연결하기 (브라우저에서 직접)

1. Cloudflare에 가입한다.
2. 대시보드에서 **Workers & Pages → 만들기**로 들어간다.
3. **Pages** 쪽으로 만들어야 한다. 처음에 Workers로 잘못 만들어서, 화면 아래쪽의 Pages로 시작하는 링크(Continue to Pages)를 눌러 다시 만들었다.
4. GitHub 저장소를 연결하고 `site` 저장소를 고른다.
5. 빌드 명령은 비우고, 결과 폴더는 저장소 맨 위(`/`)로 둔다.
6. 배포가 끝나면 `프로젝트이름.pages.dev` 주소가 생긴다.

연결한 뒤 모든 페이지가 200으로 열리고, 없는 주소는 404 페이지가 나오는지 확인했다.

## 2. 첫 게임: 마킹 탐정

수능 OMR 카드처럼 생긴 답안지에 정답을 마킹하는 추리 퍼즐이다. 정답은 숨겨져 있고, 단서만 보고 찍지 않고 맞혀야 한다.

- 게임: [마킹 탐정](https://today-ai-works.pages.dev/games/marking-detective/)

### AI에 넣은 시작 프롬프트

```text
HTML/CSS/JS 단일 파일로 "마킹 탐정"이라는 OMR 답안지 논리 퍼즐 게임을 만들어 줘. 외부 라이브러리 없이 브라우저에서 바로 실행돼야 해.

[게임 규칙]
- 문항 N개(쉬움 6, 보통 8, 어려움 10)의 정답은 각각 1~5 중 하나이고 숨겨져 있다.
- 화면에 텍스트 단서 목록이 주어지고, 플레이어는 단서로 추리해 정답을 마킹한다.
- 퍼즐은 반드시 해가 정확히 1개여야 한다.

[단서 종류] 각 단서는 { text, check(answers) } 형태로 구현:
1) A번 답 > B번 답  2) 숫자 k는 정확히 c번 등장  3) A번+B번 = s
4) A번 답은 홀수/짝수  5) A번과 B번의 답은 같다/다르다
6) 연속된 두 문항이 같은 답인 경우는 정확히 c번  7) A번 답은 k가 아니다

[퍼즐 생성]
- 무작위 정답 생성 → 정답과 일치하는 무작위 단서를 하나씩 추가하며, 5^N 전체를 탐색해 해의 개수를 센다 (어려움 모드는 백트래킹으로 최적화).
- 해가 1개가 되면, 단서를 하나씩 빼보며 여전히 유일하면 제거해 최소 단서 세트로 만든다.

[UI]
- 실제 수능 OMR 카드 느낌: 연분홍 배경, 빨간 테두리, 문항 번호 열과 ①~⑤ 타원 버블.
- 좌클릭: 검은 사인펜으로 칠한 듯한 마킹(살짝 불규칙한 질감), 한 문항에 하나만.
- 우클릭: 연필 ✕ 표시(메모용). 단서는 클릭하면 취소선으로 "사용함" 표시.
- 상단에 타이머, 난이도 선택, 새 퍼즐 버튼.
- "제출" 시 문항별로 빨간 색연필 동그라미(정답)/빗금(오답)이 그려지는 애니메이션.
- 모바일에서도 터치로 플레이 가능하게 (길게 누르기 = ✕).

코드는 섹션별 주석을 달아 읽기 쉽게 작성해 줘.
```

확장 아이디어 두 개도 같이 넣었다.

- **오늘의 퍼즐**: 날짜를 시드로 써서 모두가 같은 퍼즐을 풀고, 결과를 ⭕❌ 이모지로 공유한다 (워들처럼).
- **힌트**: 지금 확정할 수 있는 칸과 그 근거 단서를 보여 준다.

### "해가 1개"만으로는 부족했다

프롬프트대로라면 해가 1개인지만 확인하면 된다. 그런데 해가 1개여도 **사람이 추리로는 못 풀고 찍어야 하는 퍼즐**이 나올 수 있다. 그래서 기준을 바꿨다.

1. 단서를 하나 더할 때마다 "추리(후보 지우기)만으로 끝까지 풀리는지"를 확인한다.
2. 다 풀리면, 빼도 여전히 풀리는 단서는 뺀다.
3. 마지막으로 백트래킹으로 해가 정말 1개인지 한 번 더 확인한다.

이렇게 하면 찍지 않고 풀 수 있는 퍼즐만 나온다. 힌트도 같은 추리 방식으로 "이 단서 두 개를 엮으면 3번이 정해진다"를 찾아 보여 줄 수 있다. 난이도마다 40개씩 만들어 보니 모두 해가 1개였고, 하나 만드는 데 3ms가 안 걸렸다.

### 막힌 점과 해결

| 막힌 점 | 원인 | 해결 |
|---|---|---|
| "5번 + 7번 = 2" 같은 단서가 나옴 | 합이 2나 10이면 둘 다 1, 둘 다 5로 바로 정해진다 | 합이 2 · 10인 단서는 뺐다 |
| 쉬움 퍼즐이 단서 3개로 끝남 | 최소 단서 세트를 만들다 보니 너무 줄어듦 | 난이도별 최소 단서 수(쉬움 5 · 보통 7 · 어려움 9) |
| 채점 점수가 위쪽 글자와 겹침 | 같은 자리에 둘 다 표시 | 채점하면 위쪽 글자를 숨기고 그 자리에 점수 |

## 3. 영상은 "문제만" 올리기로 했다

홍보 영상을 정할 때 풀이 영상과 문제 영상 중 하나를 골라야 했다. **문제 영상만** 올리기로 했다. "이 답안지, 찍지 않고 다 맞힐 수 있는 사람?" 하고 던지고, 정답은 사이트에서 직접 풀어 보게 한다.

그러려면 영상 속 문제를 사이트에서 똑같이 풀 수 있어야 한다. 그래서 **도전 번호**를 만들었다.

- 영상에 「도전 #1」이라고 적는다.
- 사이트 홈 맨 위에 가장 최근 도전 카드가 보이고, 누르면 그 문제가 열린다 (`?c=1`).
- 인스타 프로필 링크는 홈 주소 하나로 고정한다. 영상마다 링크를 바꾸지 않아도 된다.
- 도전 목록은 파일 하나(`assets/challenges.js`)에 한 줄씩 적는다. 새 작품을 올리면 한 줄을 더한다.

도전 #1 문제는 시드 1~600번 퍼즐 중에서 골랐다. 사람이 푸는 단계를 흉내 내서 "한 번에 단서 2~3개를 엮어야 풀리는" 퍼즐(보통, 단서 7개)을 뽑았다.

### 영상 자동으로 만들기

화면 녹화 대신 프로그램으로 영상을 만들었다.

1. 게임 주소 뒤에 `?frame`을 붙이면 **영상 모드**가 된다. 화면 위아래에 「도전 #1」 문구와 안내 문구가 붙는다.
2. 브라우저 자동화 도구 Playwright가 그 화면을 1080×1920 크기로 한 장씩 찍는다.
3. ffmpeg가 사진들을 이어 mp4로 만든다.

둘 다 무료이고, 사이트 밖의 별도 폴더(`video-tools/`)에 설치했다.

```text
내 게임 페이지를 인스타 릴스용 세로 영상(1080×1920, 30fps)으로 자동 생성하는 Node.js 스크립트를 만들어 줘.
- 게임 주소에 ?frame을 붙이면 영상 모드: 사람 입력 없이 바깥에서 시간과 동작을 정할 수 있게 window.__frame 함수를 열어 줘
- Playwright로 540×960 화면을 deviceScaleFactor 2로 찍고, ffmpeg-static으로 mp4(libx264, yuv420p)로 묶어 줘
- 릴스 화면에서 가려지는 곳(위 250px, 아래 400px, 오른쪽 160px)에는 중요한 글자를 두지 마
```

처음 만든 영상은 인스타에 올리면 위아래 글자가 잘릴 것 같았다. 릴스는 위쪽(계정 이름), 아래쪽(설명 글), 오른쪽(좋아요 버튼)이 화면을 덮는다. 그래서 1080×1920 기준으로 **위 250 · 아래 400 · 오른쪽 160 · 왼쪽 60px**을 비우고, 그 안에 답안지를 줄여 넣었다. 영상 프레임 위에 이 영역을 회색으로 덮어 보면서 확인했다.

## 배운 점

- "정답이 하나"와 "사람이 풀 수 있다"는 다른 조건이다. 퍼즐은 사람이 푸는 방식을 기준으로 만들어야 한다.
- 영상은 녹화보다 **프로그램으로 찍는 쪽**이 편했다. 같은 장면을 몇 번이고 똑같이 다시 만들 수 있다.
- 인스타 프로필 링크를 하나로 고정하고, 사이트 홈이 최신 도전을 보여 주게 하니 영상을 올릴 때마다 할 일이 줄었다.
