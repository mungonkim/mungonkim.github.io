## 1주차를 줄인 이유

로드맵 1단계의 1주차는 원래 파이썬 기초(자료형, 조건문, 반복문, 함수, 리스트 · 딕셔너리, 컴프리헨션)를 일주일 동안 배우는 계획이었다. 기본 문법은 이미 알고 있어서, 일주일을 다 쓰는 대신 **점검 문제 8개**로 확인하고 막히는 부분만 복습하기로 했다.

방식은 이렇다.

- 문제마다 **테스트가 먼저** 있다. 테스트 파일이 곧 문제지다.
- 나는 함수 안을 채운다. 테스트가 모두 통과하면 끝이다.
- AI에게 정답 코드를 받지 않는다. 막히면 힌트만 받는다.

테스트를 먼저 두고 거기에 맞춰 코드를 쓰면, "무엇이 맞는 결과인지"가 처음부터 정해져 있어서 헷갈릴 일이 적다. 지난 글에서 설치한 pytest를 바로 써 보는 연습도 된다.

## 문제지 만드는 법

AI 코딩 도구에 이렇게 부탁하면 같은 형식의 문제지를 만들 수 있다.

```text
파이썬 기초를 점검하고 싶어. {점검할 범위, 예: 문자열, 딕셔너리, 정렬, 컴프리헨션, 슬라이싱}
1. 문제 8개를 함수 형태로 만들어 줘. 함수 안은 비워 두고(raise NotImplementedError),
   설명(docstring)에 조건과 예시를 적어 줘.
2. 각 함수를 확인하는 pytest 테스트를 따로 만들어 줘. 빈 값 같은 경계 상황도 넣어 줘.
3. 정답 코드는 보여 주지 마.
```

실행은 한 줄이다. 처음에는 18개가 전부 실패하고, 함수를 하나 채울 때마다 통과가 늘어난다.

```bash
uv run pytest week1 -v
```

- `-v`: 테스트마다 통과(PASSED) · 실패(FAILED)를 한 줄씩 보여 준다.
- `-k count_words`를 붙이면 이름에 `count_words`가 들어간 테스트만 돌린다. 한 문제씩 볼 때 편하다.

## 문제 8개와 푼 방법

| # | 함수 | 하는 일 | 점검 범위 |
|---|---|---|---|
| 1 | `count_words` | 문장 속 단어 수 세기 | 문자열, 딕셔너리 |
| 2 | `top_n` | 많이 나온 단어 n개 | `sorted`와 `key`, 기본값 인자 |
| 3 | `unique_in_order` | 순서를 지키며 중복 지우기 | 리스트, 집합 |
| 4 | `even_squares` | 짝수만 골라 제곱 | 리스트 컴프리헨션 |
| 5 | `group_by_category` | 상품을 카테고리별로 묶기 | 딕셔너리 안의 리스트 |
| 6 | `summarize_prices` | 최저가 · 최고가 · 평균 | 집계, 빈 값 처리, `round` |
| 7 | `parse_order` | 주문 한 줄을 나누기 | `split`, `strip`, 형 변환 |
| 8 | `chunk` | 리스트를 n개씩 나누기 | 슬라이싱, `range`의 step |

기억에 남는 풀이 몇 개를 적어 둔다.

**문제 1. 문장부호를 한 번에 지우기**

```python
text = text.lower()
text = re.sub(r'[\.,!?]', '', text)
for word in text.split():
    ...
```

`re.sub`(정규식 치환)로 마침표, 쉼표, 느낌표, 물음표를 한 번에 지웠다. `split()`을 인자 없이 쓰면 공백이 여러 개여도 알아서 나눠 준다.

**문제 2. 두 가지 기준으로 정렬하기**

"많이 나온 순서, 횟수가 같으면 가나다순"이라는 조건이었다.

```python
sorted(counts.items(), key=lambda x: (-x[1], x[0]))[:n]
```

- `counts.items()`는 `(단어, 횟수)` 묶음들이다.
- `key`에 튜플을 주면 앞 값으로 먼저 비교하고, 같으면 뒤 값으로 비교한다.
- 횟수는 **많은 순**이어야 하니 앞에 `-`를 붙여 뒤집었다. 단어는 그대로 두면 가나다순이다.

**문제 3. 순서를 지키며 중복 지우기**

```python
list(dict.fromkeys(items))
```

딕셔너리는 같은 키를 두 번 갖지 않고, 키를 넣은 순서를 기억한다. 그래서 키로 한 번 넣었다 빼면 처음 나온 순서대로 중복이 사라진다.

**문제 8. n개씩 나누기**

```python
for i in range(0, len(items), size):
    result.append(items[i:i + size])
```

`range`의 세 번째 값(step)으로 `size`씩 건너뛰고, 슬라이싱으로 잘랐다. 마지막 묶음이 모자라도 슬라이싱은 오류 없이 있는 만큼만 돌려준다.

결과는 18개 모두 통과였다.

```text
18 passed in 0.10s
```

## 예상과 달랐던 것 두 가지

다 풀고 나서 확인 질문을 받았는데, 두 개는 틀렸다.

**① `list(set(items))`로는 왜 안 될까**

중복을 지울 때 흔히 `set`을 쓴다. 나는 "set을 쓰면 정렬돼서 순서가 바뀐다"고 답했는데, 절반만 맞았다. 집합은 정렬해 주는 게 아니라 **순서를 아예 기억하지 않는다.** 작은 정수는 우연히 정렬된 것처럼 나올 때가 많아서 착각하기 쉽다. 문자열을 넣어 보면 순서가 제멋대로 나온다.

```python
list(set(["사과", "배", "포도", "사과"]))
# 실행할 때마다 순서가 달라질 수 있다
```

그래서 순서가 중요하면 문제 3처럼 `dict.fromkeys`를 쓴다.

**② `round(2.5)`는 3이 아니다**

`round(2.5)`와 `round(3.5)`를 물어봐서 3과 4라고 답했다. 실제로 실행해 보니 **2와 4**였다.

```python
round(2.5)  # 2
round(3.5)  # 4
round(0.5)  # 0
```

파이썬의 `round`는 정확히 반(.5)일 때 **가까운 짝수 쪽**으로 반올림한다. 이를 은행가 반올림이라고 한다. 반올림을 많이 하면 한쪽으로만 올라가서 생기는 오차가 쌓이지 않게 하려는 방식이다. 학교에서 배운 사사오입이 꼭 필요하면(예: 금액 계산) `decimal` 모듈을 써야 한다.

문제 6에서 평균을 `round(…, 1)`로 반올림했는데, 테스트 값은 우연히 .5가 아니어서 문제가 드러나지 않았던 것이다. 직접 실행해 보지 않았으면 계속 몰랐을 것 같다.

이럴 때 AI에 이렇게 물어보면 원리까지 설명해 준다.

```text
파이썬에서 round(2.5)가 3이 아니라 2가 나와.
왜 그런지 설명해 주고, 사사오입이 필요할 때는 어떻게 해야 하는지 예시 코드로 보여 줘.
```

## 다음 주제로 이어지는 질문

마지막 질문은 "문제 7의 `parse_order`에 칸이 하나 모자란 줄을 넣으면?"이었다.

```python
parse_order("2026-10-14,사과,3")
# IndexError: list index out of range
```

네 번째 칸(`parts[3]`)을 찾는데 칸이 세 개뿐이라 오류가 난다. 실제 데이터에는 이런 잘못된 줄이 섞여 들어오기 마련이다. 오류가 나면 프로그램 전체가 멈추게 둘지, 그 줄만 건너뛰고 기록을 남길지 정해야 한다. 이게 2주차 예외 처리의 주제다.

## 배운 점

- **테스트가 먼저 있으면 "맞는 결과"가 분명하다.** 고민할 것이 "어떻게 구현할까" 하나로 줄어든다.
- **빈 값을 꼭 생각한다.** 빈 문자열, 빈 리스트, 상품이 없을 때를 테스트가 계속 물어봤다.
- **안다고 생각한 것도 직접 실행해 본다.** set의 순서와 round는 머릿속 답과 실제 결과가 달랐다.
